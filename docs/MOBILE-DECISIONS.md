# Mobile revamp decisions

One line each: what, why, the alternative rejected.

- Tabs stay Next up, Lists, Call, Deals, More. The badges say these four are the day's work and the shell already has four plus More. Rejected: swapping Leads in (Leads is reached from Next up and More, and the count there is the biggest list, not the most urgent).
- Guide saved from the pasted text, not an attachment. No file came through, so the pasted copy is the source; em dashes replaced because CLAUDE.md bans them in docs.
- scripts/mobile-measure.mjs measures every screen in audit-screens.mjs instead of a hand walk, so milestone 1 and milestone 6 compare like with like. Rejected: a one off script in the scratchpad.
- Chrome mode is one function of the history entry (src/shell/chrome.js): an entry with an open or create request, or a path deeper than a section root, is focused. Rejected: a per route table (it drifts the moment a screen gains a sub page).
- The tab bar hides by animating its height to 0 (not a transform only), so the screen gets the space and a bar pinned above it (SaveBar) follows through --v-tabbar-now. Rejected: a fixed bar the content has to pad around.
- More is a page at /more (a tabs screen, the More tab stays current), not a sheet. The sheet and its component are deleted. Rejected: keeping both.
- A focused phone screen's top bar is Back, the title and only the actions the screen declares (useTopBar({ actions })). Search, Quick add and Notifications return with the tab bar. Rejected: keeping Search everywhere (it does nothing for the task in a record).
- Edge Back keeps a static copy of the screen it left (cloneNode at the push, skipped over 1400 elements) so the screen beneath is real, not a placeholder. Rejected: a blank ground under the moving screen.
- Edge Back calls the same Back the top bar calls, so a leave guard still applies; if the entry does not change within 360ms the screen springs back.
- The sheet's background recedes through --v-recede on .lay-root (0.96 at most), written by the Sheet itself. Backdrop clicks in the first 400ms of a sheet are ignored so the release of a long press cannot close it or press an action.
- The phone editors keep one draft in the editor and push steps as history entries (useSelection). Planner keeps the month on the overview (the job) and only Setup and the client link are steps. Rejected: making the posts a step.
- Settings on a phone is a list of rows that push the group's screen; the tab strip is computer only. A deep link to a group still opens it.
- Call room on a phone: name (two lines), priority and window, who to ask for, the Call button, then the playbook tabs Script, Objections, Close. Intel, Notes, History, socials and the descriptor are one About this lead sheet. The Call button sits above the outcome bar at 844, 700 and 568 tall.
- Row swipe on Leads (right Call, left Callback tomorrow at nine with an undo) and on planner posts (right Send for approval). Next up (done, snooze), Triage and Lists (remove) already had finger tracking and were left as they are. Every swipe action is also in the row menu.
- Long press opens a sheet (RowSheet) with the essentials and the row menu's actions on lead, client and project rows.
- eslint now runs react/jsx-no-undef: a missing component import compiled and crashed at runtime in three places before it. Rejected: relying on the smoke walks to catch it.
- The planner's Send for approval is the swipe because the client approves; Rob sends. Rejected: an approve action for Rob.
- Records push a section as a screen (open.sec on the history entry), and an intent opens its section directly. The first screen shows the stage's first section inline so the primary job never needs a tap. The earlier inline accordions moved layout after render (the Back on Projects shift of 0.18 to 0.20); the push model measures 0.002.
- The phone Call room skeleton and the phone Summary stat list (.cc-statgrid, one row per stat) are sized to the loaded states; the phone room puts everything but the playbook tabs behind About this lead.
- The layout audit skips the receded screen behind an open sheet (it is scaled to 96 percent and unreachable); the sheet's own controls still count.
- Feel audit exemptions (noFit, with the reason in scripts/audit-screens.mjs): Call Console quick builder (reached by a click, so the skeleton seen is the lists one), Calendar day (the Overdue callbacks card shows only when callbacks are overdue), the three Planner states (layout depends on the client's planner setting), Orders list (the shop order import banner depends on data), Design system (a developer page, the whole kit), Concepts editor with no set (a different page from the editor). Settings Emails card is static (reached by a tab click after load).
- Record skeletons end where the first section runs past the first screen (lead, triage, deal), and the client project card is 493px at 390, so the rows land where the loaded rows do.
- The feel audit counts the overlay's own data-v-enter as its entrance; before it only counted children, so every sheet and modal read as no entrance.
- Tasks are the existing checklists, extended (id, due, note, pinned, remindAt, notifiedAt, source) on leads and now on projects. Rejected: a tasks collection (a second system beside checklists and a new route; the rule says extend and migrate).
- The pinned task is the existing next action (auto false, taskId); Auto clears it. Rejected: a pinned flag the Next up screen reads separately from nextAction.
- The Next up rule lives in src/shared/taskRules.js and is mirrored byte for byte in api/_lib/taskRules.js, asserted by tasks-test, because a Vercel function cannot import src/. Rejected: importing src/ from api/ (it does not deploy).
- For a client or a project, an open task beats the pipeline rules in nextActionFor; a lead keeps the pipeline rules. Rejected: tasks only when the rules give nothing (the rule says Next up is the task due soonest).
- A task's reminder is sent from the task (its own remindAt and notifiedAt); the pinned next action carries no remindAt, so nothing is pushed twice.
- Suggestions are a collection with an admin route on the dispatcher (no new function) and one public action on api/planner.js. The new idea push goes out when the suggestion is written, not from a cron. Rejected: a cron pass (the daily cron would be a day late).
- Video is a format (portrait, story, video) rather than a third kind, so a video ad is kind ad, format video. Rejected: kind video (an ad with a video is still an ad).
- The planner's destination lives in the URL (?tab=posts), so a link Rob sends can open Ideas and Back on a phone returns to the tab they left. Rejected: tab state in localStorage (a shared link would open wherever the last visitor left it).
- The month arrows sit on Posts and Ads, not Home; Home names the month beside the progress line. Rejected: arrows on Home too (one more control on the first screen, and Home's job is what needs me, not browsing).
- A list's first time state is the current month with nothing in it; any other month with nothing in it says No posts this month. The public endpoint answers one month, so "ever" is not known on the page. Rejected: a total count in the endpoint (milestone 3 is UI only).
- The old legend is gone; the first time How this works card (dismissed once, remembered in localStorage, reopened from a link at the foot of Home) says the same in four lines. Rejected: both (two explanations on one screen).
- An ad's Cost section shows only when the server sent a budget (showBudget), and spend to date shows inside it; Results show reach, clicks and messages and never spend. Rejected: spend under Results (it is a cost, and a hidden budget would leak through it).
- Save to photos reads the device: navigator.canShare({ files }) says Save to photos, anything else says Download. When the fetch, the share or the download fails, the picture opens whole with "Press and hold the picture, then Save to Photos" and a link to the original with Cloudinary's fl_attachment flag. Rejected: a user agent check (iPadOS lies, and a desktop Safari can share files).
- The marketing hosts' CSP now allows connect-src and media-src to res.cloudinary.com and connect-src to api.cloudinary.com: the save fetches the original bytes, the video plays inline, and the Suggest sheet uploads through the existing unsigned preset. Cloudinary's CORS header on res.cloudinary.com could not be observed from this container (the proxy answers 403), so the fetch path is guarded by the fallback above rather than assumed.
- The Suggest sheet sends photos through the existing unsigned preset (up to 3, images only, 10 MB each, the same validateUploadFile) and offers Add a link instead the moment an upload fails or the build has no Cloudinary variables. Rejected: a second upload path or a bigger limit for the public page.
- The editor is one sheet for a post and an ad: a Post or Ad toggle at the top, the status list and the words follow the kind, the ad section appears for an ad. Rejected: a second AdSheet (two editors drift, and a video ad is still an ad).
- A video uploads through the same unsigned preset at Cloudinary's /video/upload with XMLHttpRequest for the progress bar (fetch cannot report upload progress), capped at 100MB; its poster is the asset's first frame as a JPEG. Rejected: a second preset or a signed upload (a new secret).
- The ideas inbox lives on the planner editor (a card on a computer, an Ideas step on a phone, ?ideas=1 from the push opens it). Rejected: its own screen (the ideas become posts on the same page).
- Make a post, an ad or a video from an idea creates the draft immediately (the brief as the caption, the first photo as the picture, the preferred date as the date, the goal mapped for an ad), marks the idea In the plan with the post's id, and opens the editor. Rejected: a prefilled unsaved sheet (a draft with no id cannot take an upload).
- The Planner badge counts posts in review plus ideas nobody has answered: both are somebody waiting on Rob. The drawer does not list ideas (the New idea task already sits on the client's Ideas checklist and Next up reads it).
- An ad on the calendar is one all day block per day it runs, labelled Ad, capped at 62 days, filtered under Ads. Rejected: a single block on the start date (a running ad is not a moment).
