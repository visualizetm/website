A browser reload with a failing save still loses it: that is the one case memory cannot cover and it is listed in the report.

The print sheet is the doc alone in a portal at the end of body, the app is hidden for print, and the print stylesheet is black on white with named colours (paper does not take the theme, so it is the one place that does not read `var(--v-...)`). iOS Safari's print sheet has not been tried; if it looks wrong, Copy as text stays and the PDF goes on Rob's phone test list.

A saved template uses the same tokens. Blank is never hideable, so the New doc sheet cannot be emptied; built in templates can be hidden and never deleted, and Edit a copy makes a saved one from them.
- Client docs, Make a task: the follow up line of a call note is a checklist item, and any line that starts with "Follow up" shows a Make a task button; the block menu offers it on every text block. It writes through addTask and checklistsPatch so a pinned task and the next action stay right. A doc's own checklist never becomes a task by itself.

- Client docs, one row design: DocRow (on the kit's Card) is the Docs card's row, All docs' row and the More page's row. A title wraps to two lines and is clamped there; the type is a chip, "Edited 2h ago" and a pin mark follow.

- Client docs, Settings gained a Doc templates tab (rename, edit, delete, reorder, hide), a row on the phone's Settings list and a tab on a computer. Rejected: a card inside Data, because a template list with its own menus is a screen on a phone.
- Workspace card fixes (part 5): the Showcase count was the two galleries only (brand images and website screenshots), so a published page with a cover and a logo read "0 images on the page"; the count is now every distinct image the page shows (cover, logo, brand, website, Instagram, cards, print, each only while its block is on) and a page that is published with truly none says "Published, no images yet" and never a plain Published. The state was right, the count was wrong. The Concepts card fills its middle with each direction and where it stands (Approved, Needs changes, Waiting, Picked, For reference) and the last viewed or answered line, with the button pinned to the bottom; a task title wraps to two lines and the circle sits on its first line; the channel row, the quick action chips and the formatting bar fade the edge that has more.

## Logo rollout (Brand v3)
- Staging folder: the upload landed as one commit on origin/main (55292f2, "Add files via upload"), flat, at the repo root. Pulled with a fast forward, moved with `git mv` (root icons and the manifest to `public/`, `visualize-*.svg` to `public/brand/svg/`, `visualize-*.png` to `public/brand/png/`). The checks held: the icon SVGs carry `r="192.55"`, favicon.svg is `viewBox="0 0 64 64"`, og-image.png is 1200 x 630, apple-touch-icon.png is 180 x 180. `head-snippet.html` stays at the root until M2 has applied it, then it is removed so no stray copy remains.
- Created, not uploaded: `public/badge-96.png` (the reversed icon with every fill white, 80 x 80 centered in 96 x 96; every opaque pixel is pure white, 6221 transparent pixels) and the two `-480` wordmarks (480 x 84, transparent). Rendered by `scripts/brand-render.mjs` with the Chromium the audits use; no dependency added. The V. submark files were not in the upload and nothing in this job needs them, so `Logo` has no `submark` variant.
- Logo loads the pack SVG as a file, not an inline copy (the final form is the role=img box in the entry further down). Rule 2 says inline, rule 4 says if inline would raise the hex count, load the file. The pack's fills are brand hexes and `node scripts/hex-count.js` scans src/ (it is 80 of 90), so an inline copy adds hexes to a .jsx file. Same bytes, the file is cached and the service worker precaches the ones the chrome uses. Rotating the icon file looks identical to rotating the inline SVG because the dot is at the exact center.
- "Primary logo" for the loading screen: the prompt names the spinner's tone as the primary logo, but the site and the admin are dark and `primary` is the ink version, invisible on them. The spinner uses the reversed icon (light arcs, red dot) on every dark surface, and takes `tone="primary"` for a light one. The admin's light theme is the one place that passes primary.
- LogoSpinner carries its own `<style>` (the marketing site does not load `uiStyles`), from `src/ui/logoSpinner.styles.js`, which the vite plugin also reads to paint the parser splash in index.html: one source for the component and the splash. The marketing bundle imports `src/ui/Logo` and `src/ui/LogoSpinner` by path, not the `src/ui` index, because the index pulls the whole admin kit and the public site never downloads the admin.
- The old marketing splash waited on a 1300 ms timer whatever the page was doing. The prompt forbids a minimum display time, so the timer and the splash state are gone: the spinner is the Suspense fallback and shows only while a chunk is loading, plus the parser painted one before any JS.
- The admin's session check keeps the shell skeleton frame (src/shell/bootFrame.js). The feel audit's boot rows assert that something with skeleton blocks paints before the bundle (`frame && skel`), and the layout and chrome audits measure that frame. Replacing it with a spinner fails an audit that did not assert the old logo, and the rules forbid loosening one. The admin gets the spinner everywhere else a full screen or panel waits (each screen's Suspense fallback, which was `null`, and the error and offline states it covers).
- Barlow Condensed is the display typeface of the site and the admin, not a wordmark; src/fonts.css, the tokens and the `fontDisplay` placeholder keep it. The M5 grep for `Barlow` lists those hits as explained, not removed.
- There are no email templates, PDFs or QR cards in the repo: the four emails are Zapier hooks fed by `api/_lib/email.js` payloads. M4 therefore changes no template; the hosted PNGs they need are placed under `public/brand/png/` and the footer swap is on Rob's list.
- Head tags: the pack's snippet is applied as one block in index.html, with these calls. og:title is the snippet's ("Visualize. Brand and website design for local businesses"). og:description keeps the site's own first person sentence, not the snippet's "Your vision, our creation.", because the house rule is I, never we (Rob is the only person here). The manifest link sits above the pre-paint script so the script can point the admin host at its own manifest (a vercel.json rewrite cannot, Vercel serves a file that exists before it reads rewrites); the build pins the new script hash into vercel.json by itself. `apple-mobile-web-app-title` and `mobile-web-app-capable` stay; they were not in the old block's way and the snippet does not name them.
- Two manifests, one per host: `public/site.webmanifest` is the pack's (display browser) for the public site; the admin keeps `public/manifest.webmanifest` (name, start_url, `display: standalone`, theme_color untouched) with the three pack icons, so installing the admin still installs an app.
