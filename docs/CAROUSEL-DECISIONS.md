# Carousel: decisions

The job is docs/CAROUSEL-PROMPT.md. Each call made without asking, with the rule that decided it.

1. (1) The shared module is src/shared/slides.js (slidesOf, carouselAllowed, isCarousel, SLIDES_MAX, SLIDE_ALT_MAX), mirrored byte for byte in api/_lib/slides.js; the server's cleaning (sanitizeSlides) lives in api/_routes/posts.js beside sanitizeVersion, because it needs the server's safeUrl and the mirror must stay pure.
2. (1) The count of 20 is checked after cleaning (an unsafe or empty entry dropped first): 21 real pictures are a 400; 21 entries of which two are empty are 19 pictures and fine. Plainer than refusing on entries that would never be written.
3. (1) A post that stops being a portrait post (it becomes an ad, a story or a video) has its stored slides cleared in the same write and keeps the cover as imageUrl. The brief's slidesOf has no kind check, so a stale carousel left on an ad would otherwise be drawn and sent; one rule, a stored carousel only ever on a portrait post, is easier to verify. Slides sent to an ad or a story are never written.
4. (1) A write that sends imageUrl alone to a carousel replaces slide 1 and keeps the rest behind it, so an older editor path or a script setting the cover keeps imageUrl equal to slides[0].url. An imageUrl sent beside slides never wins over the first slide.
5. (1) An empty slides array clears the carousel and leaves imageUrl as it was (the editor sends imageUrl '' with it when Rob removes every picture).
6. (1) The client's first draft (previous on /api/planner) carries the version's slides through slidesOf, so a carousel's earlier version shows every picture, not only its cover. planner-endpoint-test's previous check moves from three keys to four, the same exact key assertion.
7. (1) security-test's every-image-field section grows by the slide url (each unsafe url stored as nothing, each good one unchanged), since a slide url is a stored image link.
8. (2) A single picture post keeps its one image field exactly as before; under it, Add slides (several files at once, appended after the picture) is the way into a carousel, shown only when uploads are on. From two pictures the image field becomes the slide strip; back to one picture, the single field returns. Plainer than drawing a one slide strip for every post, and the brief asks for a single picture post to look and behave as today.
9. (2) The removal toast is the kit's own toast.undo, as every other Undo in the CRM: its enter and leave read durationMs inside the kit, and its life is the kit's undo window. A life read from durationMs would be zero under Reduce motion and the Undo would vanish before it could be pressed (existing patterns win for shared parts; a CLAUDE.md accessibility rule beats the brief).
10. (2) The slide strip is a plain list with overflow-x auto, the pattern every chip row here uses; ScrollArea is the page's vertical scroller and does not scroll sideways. Its thumbnails are keyed by url (and which copy), so a moved slide keeps its node and the focus follows it.
11. (2) A link added to the strip is checked with safeHref and must be http(s) or a root path; the server's safeUrl is still the rule. The ratio line compares each slide's measured shape with slide 1's (two percent tolerance) and names the first one that differs.
12. (2) The board card's badge class is pb-slides: pb-stack was already the board's column list class, and reusing it broke the columns' layout (found and fixed before the commit).
13. (2) Copy a month carries a carousel's slides with its cover.
14. (3) A change note on a carousel is `carouselNote` in src/lib/carousel.js: "Slide n: " before the client's words (or the reason's words), the slide the Carousel last reported, and the whole cut to the server's 500, the same cut the server makes. Review keys its post by id so the slide on view starts at 1 for each post.
15. (3) Save N to photos keeps the four steps: the save step's title reads Save N to photos (Try slide n again after a miss) and one live line under the steps carries Saving i of N, Saved N to photos or Slide n did not save. A retry that fails again opens the same press and hold sheet a single picture uses, showing that slide.
16. (3) When the files cannot all go in one share (over 50 MB, one fetch refused, or no file sharing), saveMany saves them one after another through saveMedia, as the brief says; on a phone that can share single files but not this set, that is one share sheet per picture. Logged, not changed: a second share path is what the brief rules out.
17. (3) The audits need Review to open on a carousel without approving the shared fixture's posts, so the mock has a read only token, plnrCARO, that reads L11's month with every non carousel post in review shown as approved (the same pattern as plnrCLEAR). PO32 is an approved carousel dated today for Save 5 to photos.
18. (3) On a carousel the save and open steps' help lines name the set ("They land in your photos, in order.", "Start a new post and pick all 5, in order."); the single picture lines are unchanged.
19. (3) The client app draws no edge Back gesture of its own, so inside the carousel the only edge behaviour is the browser's: the track sets overscroll-behavior-x: contain so a sideways overscroll never becomes history navigation. iOS Safari's system edge swipe is outside the page and is on the Needs Rob's phone list.
20. (3) The List's carousel line is an optional `sub` on the shared ItemRow (Ads and the day sheet pass none, so they are unchanged); the row's one control names it.
21. (3) The planner client states follow the existing split in scripts/audit-screens.mjs: a marketing entry without feel: true is walked by layout-audit.mjs (its planner walk now opens the two carousel post pages and Review on a carousel), and a11y-audit reads every entry. The new entries carry marketing: true, app: true like their neighbours.
